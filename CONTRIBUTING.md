# Contributing to AIUZ Terra Codex

This repository is a practice-and-archive branch inside the wider Terra and FMP
ecosystem.

Use it for:

- ecosystem architecture repair;
- educational, DAO, and platform documentation cleanup;
- publication-facing bridge files tied to this repository;
- detox of duplicates, mojibake, and false service surfaces.

## Before contributing

Read:

- `README.md`
- `GOVERNANCE.md`
- `DOCUMENTATION-STANDARD.md`
- `SECURITY.md`
- `CODE_OF_CONDUCT.md`

Also check the donor layer in `terra-legal` when a change affects rules,
publication, validation, or repository structure.

## What belongs here

Good contributions include:

- clarifying practice-facing AIUZ materials;
- cleaning mixed-language repository surfaces while preserving trace;
- improving public navigation and repository legibility;
- repairing citation, release, and publication metadata;
- moving misplaced residues out of the main public surface.

## What does not belong here

Do not use this repository as an uncontrolled archive dump.

Avoid:

- adding duplicate files where a stronger version already exists;
- leaving placeholder governance files;
- publishing broken exports as if they were finished artifacts;
- expanding entropy instead of reducing it.

## Working sequence

1. Read the target file and nearby files.
2. Check whether the same material exists in a stronger branch.
3. Repair encoding and structure before adding new content.
4. Keep the public-facing layer readable and English-first when appropriate.
5. Preserve trace value and repository boundaries.

## Publication and release discipline

If your change touches citation, DOI, release, or public pages:

- keep `CITATION.cff` coherent;
- do not insert fake DOI placeholders into visible surfaces;
- keep release and Zenodo workflows aligned with the repository identity.

## Security

If your change reveals a token, vulnerability, personal data issue, or unsafe
workflow behavior, use the route described in `SECURITY.md`.
